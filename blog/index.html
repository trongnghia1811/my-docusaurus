Review First Cloud AI Journey "Module 01-04 Cost optimization on AWS"

March 24, 2026 · 3 min read
Pham Trong Nghia
Administrator

Hello everyone, welcome back to Nghia's Blog! In our journey into Cloud and DevOps, we're often overwhelmed by flashy technologies like AI, Kubernetes, and Serverless. But there's an extremely practical skill, not at all glamorous, that determines the survival of a project: Cost Optimization.

Today, I'll be reviewing some incredibly valuable (literally) knowledge from the next lesson of our First Cloud AI Journey!

1. The Importance of Cost Optimization:​

  • Cost optimization is one of the two core values ​​that engineers bring to a business (besides helping the business make money). While not a particularly "new or glamorous" technology topic, it is vital and always a top priority.

2. Cost Optimization Methods on AWS:​

  • Choosing the Right Resources: Avoid bringing your entire physical server configuration (on-premise) to the cloud. On the cloud, allocate just enough configuration for current needs and scale as needed. Pay attention to the pricing of each service (e.g., storage capacity, read/write IOPS).

  • Payment Methods:

    • Reserved Instances / Savings Plans: Commit to long-term use (1 year or 3 years) to receive high discounts.

    • Spot Instances: Rent surplus AWS resources at extremely low prices, but AWS can reclaim them at any time (suitable for applications that are prone to interruptions).

  • Automatic Resource On/Off: For test or internal environments, only turn on servers during working hours (8 hours/day) and automatically turn them off at the end of the day to save costs.

  • Use Serverless or Fully Managed services: Pay based on the number of requests or actual usage instead of paying for a server running 24/7. Suitable for applications with inconsistent traffic.

  • Optimized architecture design: Refer to AWS Reference Architectures to balance technical requirements and costs.

  • Cost management (AWS Budgets & Tags):

    • Use Tags to clearly allocate costs to each department and project.
    • Set Budgets to limit budgets and receive early alerts before exceeding the allowed amount.

3. Tools and Support:​

  • Using AI (AWS Kiro CLI): Kiro can be used to automatically generate best practice checklists to optimize costs instead of doing it manually.

  • AWS Pricing Calculator: An important tool for estimating costs before actually building the system. Note that prices will vary depending on the region. For example, Malaysia or Thailand may be 10-20% cheaper than Singapore.

  • AWS Support Packages: Understand the four support packages (Basic, Developer, Business, Enterprise). For a real-world production environment, it is recommended to use at least the Business package, or Enterprise (with dedicated support engineers) for large systems.

4. Practice and Self-Study:​

  • Set up a secure AWS account (enable MFA for the Root user, create an IAM user).

  • Install AWS Budgets to manage your personal budget and avoid unexpected expenses.

  • Install and use AWS Kiro IDE & CLI.

  • Additional research: It is mandatory to independently read and learn about the AWS Well-Architected Framework to understand the core principles of designing standard cloud systems.

Review First Cloud AI Journey "Module 01-03 Gen AI on AWS - Kiro"

March 24, 2026 · 3 min read
Pham Trong Nghia
Administrator

Hello everyone, welcome back to Nghia's Blog! If our previous articles discussed cloud infrastructure, today we'll move on to a completely new and incredibly exciting chapter: The Intervention of AI in Software Development.

In particular, if you've ever wondered about the difference between a regular AI (like ChatGPT, Gemini, Claude) and an AI Agent, this summary of First Cloud AI Journey's latest video will answer all your questions!

1. The Evolution of AI in Software Development (SDLC):​

  • 2024: AI acts as an assistant, helping developers write code faster.

  • 2025: AI agents emerge capable of handling complex tasks and executing them end-to-end, with humans only playing a review role.

  • Future: Towards Autonomous Agents – fully automated agents that can work independently and collaboratively without human intervention.

2. Spec-Driven Development:​

  • When working on complex projects, simply chatting (vibe coding) with AI is insufficient and easily leads to failure.

  • Instead, Spec-Driven Development should be applied: Provide detailed descriptions and requirements of the logic, business logic, and system before starting to code. AI (like AWS Kiro) will rely on these specification documents to build a more accurate product.

3. Key Features of AWS Kiro IDE:​

  • Supports two coding methodologies: Vibe coding (free-flowing chat using natural language) and Spec-driven coding (guiding users to create detailed requirements documents before coding).

  • Kiro IDE Agent Hook: Allows setting up automated actions based on events. For example, every time a file is saved, the Agent will automatically generate/update the changelog.md file or run unit tests, optimizing the code.

  • Context Management & Steering Files: Connects Kiro with project documents so the AI ​​understands the context. Kiro can be requested to automatically generate steering files (such as product.md, structure.md) from an existing project. Supports creating user interfaces from uploaded image files.

  • Checkpoint Rollback: Saves checkpoints for easy rollback if a test idea fails or if you want to change development direction.

  • Property-Based Testing (PBT): Automatically generates and runs tests to verify whether the AI ​​code you've just written meets the business requirements specified in the Spec file.

4. Kiro CLI (Kiro Command Line Interface):​

  • Brings the power of AI Agents directly into the Terminal (supports Linux and macOS).

  • You can use natural language to build products and analyze bugs without opening the IDE.

  • Custom Agent: Allows you to create custom AI Agents for specific workflows (e.g., Agents for DevOps, Databases, or Code Review). Each Agent will be assigned permissions and provided with its own suitable toolset (MCP Server).

5. Kiro Power:​

  • To prevent AI from being "overloaded" by context (loading too many tools at once, causing slowdowns, excessive token consumption, and hallucinations), Kiro Power acts as "extended skill bundles."

  • Dynamic Loading Mechanism: AI only loads and uses the right tools/contexts when truly necessary (like giving Doraemon a "talent cassette tape"). There is a Kiro Power ecosystem contributed by AWS, partners, and the community.

6. Kiro Autonomous Agent & Enterprise Governance:​

  • Autonomous Agent: Capable of independently thinking of ways to do and execute tasks. Importantly, it can remember user feedback to avoid repeating past errors.

  • Team Governance: Provides a dashboard for managing permissions and monitoring Kiro usage across the entire enterprise team.

7. Costs and Study Recommendations:​

  • Kiro offers paid packages based on credits (e.g., $20 for 1000 credits). Within the First Cloud AI Journey program, students are encouraged to use a

  • Free Tier account (receiving 50 free credits per month) to support their studies and graduation project.

Review First Cloud AI Journey "Module 01-02 Management Console"

March 24, 2026 · 3 min read
Pham Trong Nghia

Hello everyone, welcome back to Nghia's Blog! Having grasped the fundamental concepts of Cloud Computing and AWS infrastructure in the previous lesson, today we'll begin to get hands-on with the actual system. How do we log in? What types of accounts are there? And most importantly for us developers: how do we control AWS with code instead of clicking the mouse?

Let's review the core concepts from the next video of our First Cloud AI Journey!

1. AWS Management Console and User Types:​

  • Root User: This is the original account created with email and password when you first register for AWS. It is recommended not to use this account for daily operations. Instead, enable two-factor authentication (MFA), keep it safe, and minimize its use.

  • IAM User: These are sub-accounts created from the Root User. This is the official account used to log in and interact with AWS services in practice. An Account ID (a 12-digit string) is required to log in to the IAM User.

2. AWS Management Console Interface:​

  • This is an intuitive graphical web interface (GUI). On the home page, you can search and access over 200 AWS services through the search bar or categories.

  • This interface is very suitable for beginners as it helps you easily visualize the components and easily create resources.

  • Provide a support center where users can submit requests for assistance in case of technical issues or payment-related problems (e.g., accidentally creating a resource and forgetting to close it, resulting in charges).

3. Other methods of interacting with AWS:​

Besides clicking on the Management Console interface, AWS provides two other methods for automation and programming:

  • AWS CLI (Command Line Interface): Interact with AWS through command lines. Very useful for writing scripts to automate repetitive tasks. Instead of using email/password, the CLI uses an Access Key and Secret Access Key for authentication. It is extremely important to note: these keys must be kept absolutely secure and should not be uploaded to public platforms like GitHub to avoid breaches.

  • AWS SDK (Software Development Kit): A software development kit that allows you to interact with AWS directly from the application's source code. Each programming language (such as Python, C++, Java, Node.js...) will have its own corresponding SDK. The SDK helps your application automatically call AWS APIs (for example, writing Python code to automatically create a virtual server).

Review First Cloud AI Journey "Module 01-01 - Introduction to AWS"

March 24, 2026 · 3 min read
Pham Trong Nghia
Administrator

Hello everyone, welcome back to Nghia's Blog! Continuing the series of articles on the First Cloud AI Journey (FCAJ) by AWS Study Group, in this article I will delve deeper into the foundational knowledge.

If you are aiming for UI DevOps and similar systems, then understanding the nature of Cloud Computing and how to build a global AWS platform is essential. Below is what I learned from the second video of the course.

1. New features of this year's First Cloud AI Journey program:​

  • This year's course has been upgraded to keep up with technology trends by integrating GenAI.

  • Students will become familiar with and use the AWS Q virtual assistant (Amazon Q) throughout the program. This tool will support everything from summarizing knowledge, learning, applying it to work, to completing graduation projects.

2. What is Cloud Computing?:​

  • According to AWS's definition, cloud computing is the provision of IT services over the Internet using a "pay-as-you-go" model.

  • Unlike the traditional method (which requires purchasing hardware and building expensive and high-risk data centers), Cloud Computing is like renting resources (like renting a hotel room instead of buying a house outright).

3. Benefits of Cloud Computing:​

  • Cost optimization: Pay only for the amount of resources used.

  • Speed: Enables faster product and application deployment thanks to readily available automation, AI, and security tools.

  • Service diversity: AWS now offers tens of thousands of different services/features, instead of just renting virtual servers (EC2) or storage space as in its early days.

  • Global scalability: Easily serves customers in other countries without needing to build physical infrastructure there.

4. The concept of AWS global infrastructure:​

  • Data Center: A place containing tens of thousands of servers with customized components (from CPUs and GPUs to networks) specifically for AWS.

  • Availability Zone - AZ: Consists of one or more data centers. AZs are located far apart to ensure that if one AZ fails (power outage, natural disaster), it will not affect other AZs. In practice, it is recommended to deploy applications across at least two AZs for safety.

  • Region: A region contains at least three AZs. Regions operate independently. Currently, Southeast Asia has regions such as Singapore, Malaysia, and Thailand.

  • Edge Location and POP (Point of Presence): These are edge data centers that provide services such as CloudFront (CDN). AWS now has Edge Locations in Hanoi and Ho Chi Minh City, enabling significantly faster loading of static files (images, videos) for users in Vietnam.

  • Local Zone: Like a miniature AZ, located locally (for example, in Vietnam and directly connected to the Singapore Region) to minimize latency and meet local data security standards.

What is CPython?

February 2, 2026 · 5 min read
Pham Trong Nghia
Administrator

In this article, I will share what I know from learning about CPython.

  • What is CPython?
  • How does the journey from a line of code in the IDE to execution happen?
  • How does CPython manage memory?

1. What is CPython?​

Before going into detail, we need to clarify: Python is a language (a set of grammatical rules). CPython is the software that executes those rules (Implementation).

When we download Python from the homepage, we are actually downloading CPython. It is written entirely in C. It acts as both a Compiler and an Interpreter.

2. The Journey of Code: Pipeline from A to Z​

Consider the following example:

a = 10
print(a + 5)

For the computer to understand, this line of code must go through a strict process consisting of 4 stages:

Stage 1: Lexing (Lexical Analysis)​

CPython reads our code file as a meaningless string of text. The Lexer will chop that string into meaningful units called Tokens.

a -> NAME
= -> OP
10 -> NUMBER

Python's Lexer is very special: it also cares about whitespace (indentation) to generate INDENT and DEDENT tokens, helping to shape the code blocks.

Stage 2: Parsing & AST (Building the Abstract Syntax Tree)​

From the discrete tokens above, the Parser will arrange them according to the grammar and build an Abstract Syntax Tree (AST). The computer doesn't read from left to right like humans; it looks at the tree structure to know which is the parent, which is the child, and which has execution priority (e.g., multiplication and division first, addition and subtraction later).

Stage 3: Compilation (Compiling to Bytecode)​

At this point, an extremely important step takes place: CPython is forced to translate the AST into an intermediate language called Bytecode (.pyc).

  • Note: Python does not directly run the source code (.py) line by line as many people mistakenly believe.

  • It always has to Compile to Bytecode first. This Bytecode is not Machine Code for the CPU to run, but an instruction set specifically for the Python virtual machine.

Giai đoạn 4: Python Virtual Machine (PVM)​

This is where the program actually runs. The PVM is an infinite loop that acts as a "virtual CPU". With the statement a = 10, the memory model operates entirely differently from traditional C/Java:

  • Heap Memory (Contains Objects): The PVM creates an int object with a value of 10 located on the Heap.

  • Stack Memory (Contains References): The PVM pushes the variable name a (reference) onto the current Stack frame and points it to the address of the object 10 on the Heap.

Key difference: The Stack in Python does not contain "values"; it only contains references. Everything in Python (numbers, strings, booleans...) is an Object and resides on the Heap. Finally, the PVM reads each line of Bytecode and calls the corresponding C functions for the CPU to execute.

3. How does CPython manage memory?​

CPython manages memory extremely sophisticatedly.

Everything is an Object (PyObject)​

In CPython, the number 10 is not just 4 binary bytes. It is a C struct named PyObject. It contains a lot of metadata:

  • What type is it (int, str)?
  • How many references are currently using it (Reference Count)?

Pymalloc & Allocation Mechanism​

CPython does not call malloc (requesting RAM from the OS) every time we create a variable, because that is very slow. Instead, it uses Pymalloc:

  • It pre-allocates large chunks of memory (Arenas).
  • Subdivides them into pools (Pools).
  • When we need it, it immediately "issues" a small block. This is why creating small objects in Python is very fast.

Garbage Collection​

How does Python know when to delete a variable to free up RAM?

  1. Reference Counting (Primary): Each object has a counter. Whenever a variable references it, the count is +1; when it's no longer used (or del is used), it's -1. When the counter reaches 0, the object is deleted immediately.

  2. Generational Garbage Collection (Handling Cyclic References):

  • Problem: If A points to B, and B points back to A (Reference Cycle), the Reference Count of both will never reach 0, even if we no longer use them. This is a memory leak.

  • Solution: CPython uses a Generational Garbage Collector. It periodically scans "container" objects (lists, dicts, classes...) to detect these closed cycles and clean them up.

4. Conclusion​

The journey from a line of code in the IDE to when the OS executes it is a long path through the Lexer, Parser, Compiler, and PVM. CPython is not just an interpreter; it is an engineering masterpiece that combines the flexibility of a high-level language with the strictness of C.

Hopefully, this article gives you a deeper insight into the tool you use every day. Don't just code; understand how the code runs!
