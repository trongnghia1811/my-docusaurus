Tìm hiểu Java Platform – Execution Flow & JVM Architecture

November 2, 2026 · 5 min read
Phạm Trọng Nghĩa
Quản trị viên

1. Java Platform Overview – Tổng quan nền tảng Java​

Java không chỉ là một ngôn ngữ lập trình, mà là một nền tảng hoàn chỉnh (Java Platform).

👉 Khi nói “lập trình Java”, thực chất ta đang làm việc với 3 thành phần cốt lõi:

  • Java Language
  • JVM (Java Virtual Machine)
  • Hệ sinh thái thư viện & công cụ

Mục tiêu cốt lõi của Java​

Write Once, Run Anywhere (WORA)

Viết code một lần, chạy được trên:

  • Windows
  • Linux
  • macOS
    … mà không cần sửa code

2. Vai trò của JDK, JRE, JVM​

Rất nhiều người học Java bị nhầm lẫn 3 khái niệm này, nên cần làm rõ tuyệt đối.

2.1 JVM – Java Virtual Machine​

JVM là gì?

  • JVM là máy ảo
  • Chạy bytecode Java
  • Đóng vai trò trung gian giữa Java và hệ điều hành

📌 JVM:

  • Không hiểu .java
  • Không hiểu .exe
  • Chỉ hiểu .class (bytecode)

👉 Mỗi hệ điều hành có JVM riêng, nhưng:

  • Bytecode thì giống nhau

2.2 JRE – Java Runtime Environment​

JRE gồm:

  • JVM
  • Core Java Libraries (java.lang, java.util, ...)
  • Các file cấu hình runtime

👉 JRE dùng để:

  • Chạy chương trình Java
  • ❌ Không dùng để viết hay biên dịch code

📌 Nếu máy chỉ có JRE:

  • Chạy được .class
  • ❌ Không biên dịch được .java

2.3 JDK – Java Development Kit​

JDK = JRE + Công cụ phát triển

Bao gồm:

  • javac (compiler)
  • java (launcher)
  • javadoc, jdb, ...

👉 JDK dùng để:

  • Viết code
  • Biên dịch
  • Chạy
  • Debug

📌 Khi cài Java để học lập trình: ➡️ LUÔN cần JDK

2.4 Mối quan hệ tổng thể​

JDK
├── JRE
│ ├── JVM
│ └── Java Core Libraries
└── Development Tools

3. Mối quan hệ giữa Java Language và Java Platform​

Java Language​

  • Cú pháp và từ khóa
  • Kiểu dữ liệu
  • OOP (class, object, inheritance)
  • File mã nguồn .java

Java Platform​

  • JVM (Java Virtual Machine)
  • ClassLoader Subsystem
  • Runtime Data Areas
  • Execution Engine & Garbage Collector

Java Language chỉ là phần nổi
Java Platform mới là thứ quyết định chương trình chạy thế nào

4. Java Execution Flow – Luồng thực thi của Java​

Khi bạn chạy một chương trình Java, JVM không thực thi trực tiếp file .java.

Luồng tổng quát​

IDE
↓ (Save)
Hello.java (Ổ cứng)
↓ (Compile)
javac Hello.java
↓
Hello.class (Bytecode)
↓

JVM (RAM)
↓
OS
↓
CPU thực thi

5. Compile-time và Runtime trong Java​

5.1 Compile-time​

Xảy ra khi chạy:

javac Hello.java

Đầu vào:

File .java (source code)

Java làm gì? -Kiểm tra cú pháp -Kiểm tra kiểu dữ liệu -Biên dịch sang bytecode

Đầu ra: -File .class

📌 Compile-time không chạy chương trình

5.2 Runtime​

Xảy ra khi chạy:

java Hello

Đầu vào: -File .class

Java làm gì? -JVM load class -Kiểm tra bytecode

Thực thi 📌 Runtime mới là lúc chương trình thực sự chạy

6. Bytecode là gì? Vì sao Java portable?​

Bytecode là gì? -Là mã trung gian -Không phải mã máy -Không phụ thuộc OS hay CPU

📌 Bytecode: -Chạy trên JVM -JVM dịch tiếp sang mã máy

Vì sao Java chạy đa nền tảng?

Java Source (.java)
↓
Bytecode (.class)
↓
┌─────────────┐
│ JVM Windows │ → CPU Windows
│ JVM Linux │ → CPU Linux
│ JVM macOS │ → CPU macOS
└─────────────┘

👉 Không phải Java chạy trực tiếp trên OS 👉 JVM mới là thứ chạy trên OS

7. JVM Architecture – Kiến trúc JVM​

JVM gồm 3 khối lớn: -ClassLoader Subsystem -Runtime Data Areas -Execution Engine

8. ClassLoader Subsystem​

Nhiệm vụ: -Load .class vào JVM -Kiểm tra tính hợp lệ -Chuẩn bị class để chạy

Các loại ClassLoader trong JVM​

  • Bootstrap ClassLoader
    Load các core class của Java (ví dụ: java.lang, java.util)

  • Platform ClassLoader (Java 9+)
    Load các thư viện thuộc Java Platform (ví dụ: java.sql, java.xml)

  • Application ClassLoader
    Load các class do lập trình viên viết (classpath) 📌 Class chỉ được load khi cần thiết

9. Runtime Data Areas – Vùng nhớ trong JVM​

9.1 Method Area​

Lưu: -Class metadata -Method info -Static variables

9.2 Heap​

-Lưu object -Dùng chung cho toàn JVM -Do Garbage Collector quản lý

9.3 Stack​

Mỗi thread có stack riêng

Lưu: -Local variables -Method call -Reference

📌 Stack nhỏ, nhanh 📌 Heap lớn, chậm hơn

9.4 PC Register​

Lưu địa chỉ instruction đang chạy

9.5 Native Method Stack​

Dùng cho code native (C/C++)

10. Execution Engine – Bộ máy thực thi​

10.1 Interpreter​

Đọc bytecode

Thực thi từng instruction

📌 Ưu điểm: -Chạy ngay

📌 Nhược điểm: -Chậm nếu chạy lặp nhiều lần

10.2 JIT Compiler (Just-In-Time)​

JIT làm gì? -Phát hiện đoạn code chạy nhiều -Biên dịch bytecode → mã máy -Cache lại để dùng sau

📌 JVM hiện đại: -Interpreter + JIT -Tự tối ưu khi chương trình chạy

Java không đơn thuần là một ngôn ngữ, mà là một nền tảng hoàn chỉnh gồm JDK, JRE và JVM. Chương trình Java không chạy trực tiếp trên hệ điều hành mà phải trải qua quá trình biên dịch sang bytecode, sau đó được JVM thông dịch và tối ưu bằng JIT trước khi CPU thực thi.

CPython là gì?

February 2, 2026 · 5 min read
Phạm Trọng Nghĩa
Quản trị viên

Trong bài viết này, mình sẽ chia sẻ về những gì mình biết khi tìm hiểu về CPython.

  • CPython là gì?
  • Hành trình từ dòng code xuống IDE diễn ra thế nào?
  • Cách CPython quản lý bộ nhớ?

1. CPython là gì?​

Trước khi đi vào chi tiết, chúng ta cần làm rõ: Python là ngôn ngữ (tập hợp các quy tắc ngữ pháp). Còn CPython là phần mềm thực thi các quy tắc đó (Implementation).

Khi ta tải Python từ trang chủ về tức là ta đang tải CPython. Nó được viết hoàn toàn bằng C. Nó vừa là Compiler (biên dịch), vừa là Interpreter (thông dịch).

2. Hành trình của Code: Pipeline từ A đến Z​

Cho ví dụ sau:

a = 10
print(a + 5)

Để máy tính hiểu được, dòng code này phải trải qua một quá trình nghiêm ngặt gồm 4 giai đoạn:

Giai đoạn 1: Lexing (Phân tích từ vựng)​

CPython đọc file code của ta như một chuỗi văn bản vô nghĩa. Lexer sẽ băm nhỏ chuỗi đó thành các đơn vị có nghĩa gọi là Tokens.

a -> NAME
= -> OP
10 -> NUMBER

Lexer của Python rất đặc biệt: nó quan tâm đến cả khoảng trắng (indentation) để sinh ra các token INDENT và DEDENT, giúp định hình khối lệnh.

Giai đoạn 2: Parsing & AST (Xây dựng cây cú pháp trừu tượng)​

Từ những token rời rạc trên, Parser sẽ sắp xếp chúng lại theo ngữ pháp và dựng lên một Cây Cú pháp Trừu tượng (Abstract Syntax Tree - AST). Máy tính không đọc từ trái sang phải như người, nó nhìn cấu trúc cây để biết cái nào là cha, cái nào là con, cái nào ưu tiên thực hiện trước (ví dụ: nhân chia trước, cộng trừ sau).

Giai đoạn 3: Compilation (Biên dịch sang Bytecode)​

Đến đây, một bước cực kỳ quan trọng diễn ra: CPython bắt buộc phải dịch AST sang một ngôn ngữ trung gian gọi là Bytecode (.pyc).

  • Lưu ý: Python không chạy trực tiếp source code (.py) từng dòng một như nhiều người lầm tưởng.

  • Nó luôn phải Compile sang Bytecode trước. Bytecode này không phải là Mã máy (Machine Code) để CPU chạy, mà là tập lệnh dành riêng cho máy ảo Python.

Giai đoạn 4: Python Virtual Machine (PVM)​

Đây là nơi chương trình thực sự chạy. PVM là một vòng lặp vô tận, hoạt động như một "CPU ảo". Với lệnh a = 10, mô hình bộ nhớ hoạt động khác hẳn với C/Java truyền thống:

  • Heap Memory (Chứa Object): PVM tạo một object int có giá trị là 10 nằm trên Heap.

  • Stack Memory (Chứa Reference): PVM đẩy cái tên biến a (reference) vào Stack frame hiện tại và trỏ nó tới địa chỉ của object 10 bên Heap.

Khác biệt mấu chốt: Stack trong Python không chứa "giá trị" (value), nó chỉ chứa các tham chiếu. Mọi thứ trong Python (số, chuỗi, boolean...) đều là Object và nằm trên Heap. Sau cùng, PVM đọc từng dòng Bytecode, gọi các hàm C tương ứng để CPU thực thi.

3. Cách CPython quản lý bộ nhớ?​

CPython quản lí bộ nhớ cực kì tinh vi

Mọi thứ đều là Object (PyObject)​

Trong CPython, số 10 không chỉ là 4 bytes nhị phân. Nó là một struct (cấu trúc) trong C tên là PyObject. Nó chứa rất nhiều metadata:

  • Nó thuộc kiểu gì (int, str)?
  • Có bao nhiêu người đang dùng nó (Reference Count)?

Pymalloc & Cơ chế cấp phát​

CPython không gọi malloc (xin RAM từ OS) mỗi khi ta tạo một biến, vì việc đó rất chậm. Thay vào đó, nó dùng Pymalloc:

  • Nó xin sẵn những vùng đất lớn (Arenas).
  • Chia nhỏ thành các hồ (Pools).
  • Khi ta cần, nó "phát" ngay một mảnh nhỏ. Đây là lý do tạo object nhỏ trong Python rất nhanh.

Dọn rác (Garbage Collection)​

Làm sao Python biết khi nào xóa biến để giải phóng RAM?

  1. Reference Counting (Chủ đạo): Mỗi object có một bộ đếm. Cứ ai dùng biến thì đếm +1, không dùng nữa (hoặc dùng del) thì -1. Khi bộ đếm về 0, object bị xóa ngay lập tức.

  2. Generational Garbage Collection (Xử lý Cyclic Reference):

  • Vấn đề: Nếu A trỏ tới B, và B trỏ ngược lại A (Vòng tham chiếu), thì Reference Count của cả hai không bao giờ về 0, dù ta không dùng chúng nữa. Đây là rò rỉ bộ nhớ.

  • Giải pháp: CPython sử dụng một bộ gom rác thế hệ (Generational GC). Nó định kỳ quét các object dạng "container" (list, dict, class...) để phát hiện các vòng tròn khép kín này và dọn dẹp chúng.

4. Kết luận​

Hành trình từ dòng code trên IDE đến khi OS thực thi là một chặng đường dài đi qua Lexer, Parser, Compiler và PVM. CPython không chỉ là một trình thông dịch, nó là một kiệt tác kỹ thuật kết hợp giữa sự linh hoạt của ngôn ngữ bậc cao và sự chặt chẽ của C.
