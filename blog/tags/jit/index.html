Tìm hiểu Java Platform – Execution Flow & JVM Architecture

November 2, 2026 · 6 min read
Phạm Trọng Nghĩa
Quản trị viên

1. Java Platform Overview – Tổng quan nền tảng Java​

Nhiều người khi mới tiếp cận thường nghĩ Java đơn thuần chỉ là một ngôn ngữ lập trình. Trên thực tế, Java được thiết kế như một nền tảng hoàn chỉnh (Java Platform), bao gồm nhiều thành phần phối hợp chặt chẽ với nhau để chương trình có thể chạy ổn định trên nhiều hệ điều hành khác nhau..

👉 Khi nói “lập trình Java”, thực chất ta đang làm việc với 3 trụ cột chính:

  • Java Language - cú pháp và quy tắc viết chương trình
  • JVM (Java Virtual Machine) - môi trường thực thi
  • Hệ sinh thái thư viện & công cụ - hỗ trợ phát triển và chạy ứng dụng

Triết lý cốt lõi của Java là:​

Write Once, Run Anywhere (WORA)

Điều này có nghĩa là:

Code Java chỉ cần viết một lần

Có thể chạy trên Windows, Linux, macOS…

Không cần chỉnh sửa mã nguồn cho từng hệ điều hành

2. Phân biệt rõ JDK – JRE – JVM (điểm dễ nhầm nhất)​

Đây là phần bắt buộc phải hiểu đúng, vì rất nhiều người học Java lâu năm vẫn nhầm lẫn ba khái niệm này.

2.1 JVM – Java Virtual Machine​

JVM là một máy ảo, không tồn tại vật lý, nhưng đóng vai trò trung tâm trong việc chạy chương trình Java.

Đặc điểm quan trọng của JVM:

  • Không đọc được file .java
  • Không hiểu file .exe
  • Chỉ thực thi file .class (bytecode)

Nhiệm vụ chính của JVM:

  • Làm cầu nối giữa chương trình Java và hệ điều hành
  • Quản lý bộ nhớ
  • Tối ưu và thực thi mã lệnh

📌 Mỗi hệ điều hành có JVM riêng (Windows JVM, Linux JVM, macOS JVM), nhưng bytecode Java là giống nhau trên mọi nền tảng.

2.2 JRE – Java Runtime Environment​

JRE là môi trường dùng để chạy chương trình Java.

JRE bao gồm:

  • JVM
  • Thư viện chuẩn của Java (java.lang, java.util, java.io, …)
  • Các thành phần cấu hình runtime

👉 JRE chỉ dùng để chạy chương trình, không phục vụ phát triển.

📌 Nếu máy chỉ cài JRE:

Chạy được file .class

❌ Không thể biên dịch file .java

2.3 JDK – Java Development Kit​

JDK là bộ công cụ dành cho lập trình viên Java.

JDK bao gồm:

  • JRE
  • Trình biên dịch javac
  • Trình chạy java
  • Các công cụ hỗ trợ khác: javadoc, jdb, …

👉 JDK cho phép:

  • Viết code
  • Biên dịch
  • Chạy
  • Debug chương trình

📌 Muốn học hoặc làm Java → luôn phải cài JDK

2.4 Mối quan hệ tổng thể​

JDK
├── JRE
│ ├── JVM
│ └── Java Core Libraries
└── Development Tools

3. Mối quan hệ giữa Java Language và Java Platform​

Hai khái niệm này không giống nhau, nhưng thường bị dùng lẫn.

Java Language

  • Cú pháp
  • Kiểu dữ liệu
  • Lập trình hướng đối tượng (class, object, inheritance, polymorphism)
  • File mã nguồn .java

Java Platform

  • JVM
  • ClassLoader
  • Runtime Memory
  • Execution Engine
  • Garbage Collector

👉 Java Language chỉ là phần “viết code” 👉 Java Platform mới quyết định chương trình chạy như thế nào

4. Java Execution Flow – Luồng thực thi của Java​

JVM không bao giờ chạy trực tiếp file .java.

Quy trình thực thi tiêu chuẩn:

IDE
↓ (Save)
Hello.java (Ổ cứng)
↓ (Compile)
javac Hello.java
↓
Hello.class (Bytecode)
↓

JVM (RAM)
↓
OS
↓
CPU thực thi

📌 File .class mới là đầu vào thực sự của JVM.

5. Compile-time và Runtime trong Java​

5.1 Compile-time​

Xảy ra khi chạy lệnh:

javac Hello.java

Java sẽ:

  • Kiểm tra cú pháp
  • Kiểm tra kiểu dữ liệu
  • Biên dịch mã nguồn sang bytecode

Kết quả:

  • Tạo ra file .class
  • Chương trình chưa chạy

5.2 Runtime​

Xảy ra khi chạy:

java Hello

Đầu vào: -File .class

Lúc này JVM:

  • Load class
  • Verify bytecode
  • Thực thi chương trình

📌 Runtime mới là thời điểm chương trình thực sự hoạt động.

6. Bytecode là gì? Vì sao Java portable?​

Bytecode là gì?

  • Mã trung gian
  • Không phụ thuộc CPU hay hệ điều hành
  • Được thiết kế riêng cho JVM

📌 Bytecode: -Chạy trên JVM -JVM dịch tiếp sang mã máy

Vì sao Java chạy đa nền tảng?

Java Source (.java)
↓
Bytecode (.class)
↓
┌─────────────┐
│ JVM Windows │ → CPU Windows
│ JVM Linux │ → CPU Linux
│ JVM macOS │ → CPU macOS
└─────────────┘

👉 Java không chạy trực tiếp trên OS 👉 JVM mới là thứ giao tiếp trực tiếp với hệ điều hành

7. JVM Architecture – Kiến trúc JVM​

JVM được chia thành 3 khối chính:

  • ClassLoader Subsystem
  • Runtime Data Areas
  • Execution Engine

8. ClassLoader Subsystem​

Nhiệm vụ:

  • Load .class vào JVM
  • Kiểm tra tính hợp lệ
  • Chuẩn bị class cho quá trình thực thi

Các loại ClassLoader trong JVM​

  • Bootstrap ClassLoader
    Load các core class của Java (ví dụ: java.lang, java.util)

  • Platform ClassLoader (Java 9+)
    Load các thư viện thuộc Java Platform (ví dụ: java.sql, java.xml)

  • Application ClassLoader
    Load các class do lập trình viên viết (classpath) 📌 Class chỉ được load khi cần thiết

9. Runtime Data Areas – Vùng nhớ trong JVM​

9.1 Method Area​

Lưu: -Class metadata -Method info -Static variables

9.2 Heap​

-Lưu object -Dùng chung cho toàn JVM -Do Garbage Collector quản lý

9.3 Stack​

Mỗi thread có stack riêng

Lưu: -Local variables -Method call -Reference

📌 Stack nhỏ, nhanh 📌 Heap lớn, chậm hơn

9.4 PC Register​

Lưu địa chỉ instruction đang chạy

9.5 Native Method Stack​

Dùng cho code native (C/C++)

10. Execution Engine – Bộ máy thực thi​

10.1 Interpreter​

  • Đọc bytecode
  • Thực thi từng instruction

📌 Ưu điểm:

  • Chạy ngay

📌 Nhược điểm:

  • Chậm nếu chạy lặp nhiều lần

10.2 JIT Compiler (Just-In-Time)​

JIT làm gì?

  • Phát hiện đoạn code chạy nhiều
  • Biên dịch bytecode → mã máy
  • Cache lại để dùng sau

📌 JVM hiện đại:

  • Interpreter + JIT
  • Tự tối ưu khi chương trình chạy
